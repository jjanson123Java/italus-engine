First-Time Author Guide

How to Use Italus Studio

This guide walks you through the exact order of operations for building a narrative project: create the project, set the token budget, build canon files, create the book structure, generate scenes, and validate continuity.

1. Start Here: What ITALUS Does

ITALUS is a browser-based narrative workspace. You, the author, define the story world, characters, timeline, rules, and scene goals. The backend organizes that information into project context, canon packets, prompts, generation requests, and validation results.

Author rule: Do not begin generation until the project has a token budget and basic canon files. Without canon, the system has no stable truth to preserve.

2. Landing Portal

The landing portal is the entry point. It is not where writing happens. It is where you choose what kind of project session to begin.

File

Use Home to return to the landing page. Use exit only when the application later confirms the project is safe to close.

Project

Use New Project when starting a new story world. Use Existing Project to resume active work. Use Archived Project for read-only or retired work.

Settings

Use settings before serious generation to configure theme, provider preferences, and project behavior. Token budget belongs to project setup and must be reviewed early.

Help

Use Help when you need workflow guidance. API Health checks whether the backend server is alive.

3. New Project Workflow

A new project is not just an empty writing page. It is a controlled workspace with its own identity, token budget, canon files, book structure, and validation rules.

  1. Click Project → New Project. The browser opens the workspace in new-project mode.
  2. Name the project. Use a durable name, not a temporary idea. Example: The Ashen Crown.
  3. Choose the narrative type or genre. This helps future templates, validation rules, and generation behavior.
  4. Set the token budget. This controls how much context the system may load into prompts. Larger budgets allow more canon and scene context, but cost more and can slow generation.
  5. Create canon files before writing scenes. Canon files are the source of truth for world rules, characters, timeline, locations, and style.
  6. Create the first book record. A project may contain multiple books. The book becomes the container for chapters, events, and scenes.
  7. Create chapters, events, or scenes. This gives generation a specific target instead of asking the system to write blindly.
  8. Build the first prompt. The prompt should reference the current scene goal, relevant canon, characters, and continuity needs.
  9. Generate, review, then validate. Generation creates text. Validation checks whether the text obeys the project canon.
Common mistake: New authors often click Generate too early. The correct first work is project setup, token budget, and canon creation.

4. Token Budget Setup

The token budget is the project’s context limit. It determines how much information can be sent into generation and validation at one time.

Why it matters

Canon, scene instructions, prior events, character state, and style rules all compete for space. A weak budget creates shallow prompts. An uncontrolled budget creates cost and performance risk.

What to decide

Decide whether the project needs short-scene drafting, long chapter drafting, deep canon loading, or validation-heavy workflows.

Author action

Set the budget before creating generation workflows. Revisit it when the project grows.

Backend action

The backend will later use this setting to limit prompt assembly, canon packet size, and validation scope.

5. Canon Files: The First Real Author Task

Canon files are the controlled truth of the project. They prevent the story from drifting. Before serious generation, create at least the core canon files below.

World Canon

Defines the setting, laws of the world, history, factions, technology, magic, religion, political structures, and hard rules the story must obey.

Character Canon

Defines names, roles, goals, wounds, relationships, voice, appearance, secrets, and what each character knows at each stage of the story.

Timeline Canon

Defines what happened, when it happened, what has not happened yet, and what events cannot be contradicted.

Location Canon

Defines places, geography, rooms, travel limits, atmosphere, access rules, and recurring visual details.

Style Canon

Defines tone, prose style, banned phrases, point of view, tense, pacing, and genre expectations.

Continuity Rules

Defines what the validator must protect: injuries, deaths, travel time, relationship state, unresolved clues, promises, objects, and cause-effect chains.

  1. Create or import the canon file.
  2. Assign the canon type.
  3. Attach it to the active project.
  4. Review it for contradictions.
  5. Allow the backend to package it later into canon packets for generation and validation.

6. Workspace Overview

The workspace is where the application becomes active. Each pane has a specific purpose.

Project Explorer

Shows project structure: books, chapters, events, scenes, canon files, and generated artifacts. Start here after project creation.

Author Workspace

The central writing surface. Use it to draft prompts, review generated prose, and revise scene text.

Inspector

Shows metadata, selected item details, canon links, validation status, and future Guardian guidance.

Runtime Console

Shows backend activity, route status, generation status, validation results, and system warnings.

7. Recommended Author Workflow

  1. Create project. Establish the project container.
  2. Set token budget. Define context limits before generation.
  3. Create canon files. Build the source of truth.
  4. Create book. Define the first major story container.
  5. Create chapter or event. Add structure before scene generation.
  6. Create scene. Define point of view, location, characters, and scene goal.
  7. Build prompt. Combine author intent with selected canon and scene context.
  8. Generate. Backend sends a controlled request to the generation service.
  9. Validate. Backend checks continuity, canon, timeline, character, and location consistency.
  10. Revise. The author accepts, edits, regenerates, or repairs the scene.

8. What the Backend Does

The backend owns lifecycle, state, orchestration, generation, canon packaging, and validation. The frontend should never directly decide whether project state is valid.

Browser UI FastAPI Routes Project Service Canon Service Generation Service Validation Service

When you click a workspace action, the browser should call an API route. The route delegates to a service. The service loads project context, prepares canon, performs the requested workflow, and returns a structured result to the browser.

9. Validation Workflow

Validation protects the story from uncontrolled drift. It should happen after generation and before the author treats generated text as accepted canon.

Continuity Validation

Checks whether events, injuries, promises, objects, and knowledge remain consistent.

Canon Validation

Checks whether generated text violates established world, character, location, or style canon.

Timeline Validation

Checks whether the scene occurs in the correct order and respects elapsed time.

Character Validation

Checks whether characters speak, act, and know things consistent with their current state.
