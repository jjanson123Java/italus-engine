CANON MEMORY ENGINE — INTERNAL DATA FLOW

THIS IS THE ACTUAL GENERATION PIPELINE.

author request
      │
      ▼
menu/controller
      │
      ▼
generate_scene_payload()
      │
      ▼
process_request()
      │
      ├ resolve canon context
      │
      ├ load session state
      │
      ├ duplicate detection
      │
      ├ coverage analysis
      │
      ├ prompt_builder
      │
      ▼
ai_runner.generate_with_ai()
      │
      ▼
AI provider
      │
      ▼
generated prose
      │
      ▼
payload returned to UI



CANON COMMIT PIPELINE

WHEN THE AUTHOR ACCEPTS A SCENE:

generated scene
      │
author edits / confirms
      │
      ▼
save_accepted_scene_payload()
      │
      ▼
save_accepted_scene()
      │
      ├ backup canon files
      ├ ensure chapter exists
      ├ create scene record
      ├ update coverage
      ├ update chapter digest
      ├ update book state
      └ update session state
      ▼
scene committed to canon




CANON MEMORY STATE

THE ENGINE REMEMBERS CONTINUITY THROUGH THESE FILES:

data/
├ book_state.json
│
├ chapter_continuity_digests.json
│
├ scenes/
│   ├ scene_001.json
│   ├ scene_002.json
│   └ ...
│
└ backups/

These allow the engine to:

track narrative progress
prevent duplicate scenes
maintain historical continuity
resume writing sessions
