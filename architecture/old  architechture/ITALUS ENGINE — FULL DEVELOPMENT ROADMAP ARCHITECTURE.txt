New systems introduced in Phase 2
Canon Memory Engine

Persistent memory for narrative continuity.

data/
 ├ book_state.json
 ├ chapter_continuity_digests.json
 ├ scenes/
 └ backups/

Responsibilities:

track narrative progress
detect duplicate scenes
maintain timeline continuity
resume writing sessions
store accepted scenes
Canon Commit Pipeline

When an author accepts a scene:

generated scene
     │
author edits
     │
     ▼
save_accepted_scene()
     │
     ├ backup canon files
     ├ create scene record
     ├ update chapter digest
     ├ update book state
     └ update session state

This makes the engine stateful.

AI Provider Abstraction
ai_runner.py
     │
     ├ claude_runner.py
     ├ openai_runner.py
     └ novelcraft_runner.py

Purpose:

allow multiple AI providers

normalize responses

switch models without rewriting engine logic

PHASE 4 — CANON PACKET ENGINE

(Continuity safeguard layer)

This phase introduces Canon Packet Assembly.

project_runner
      │
      ▼
Canon Packet Builder
      │
      ├ Canon Pack ordering
      ├ metadata validation
      ├ packet integrity checks
      └ runtime memory injection
      │
      ▼
prompt_builder

Canon packet contains:

CORE canon
GENERATION canon
BOOK canon
chapter digest
book state
event metadata

Purpose:

guarantee canon ordering

prevent missing canon layers

prevent corrupted prompts
