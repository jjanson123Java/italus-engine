ITALUS ENGINE — ARCHITECTURAL GOALS (UPDATED)
Generated: 2026-03-11

PURPOSE
-------
This document defines the CURRENT WORKING ARCHITECTURE the Italus engine is now following.

It replaces the older understanding where drift_precheck acted as a mixed-role validator.
The correct architecture now separates:
- Canon Packet Engine
- Guardian Engine
- post_generation_canon_validator
- Canon Memory Engine
- commit pipeline

BOOK PACK CANON NOTE
--------------------
"Book pack canon" and "compressed book pack canon" are the SAME artifact.
They are not separate layers of canon authority.
The difference is only runtime usage footprint, not canon status.

AUTHORITATIVE CANON LAYERS
--------------------------
1. Global canon
   - ITALUS_KNOWLEDGE_PACK_CORE.txt
   - ITALUS_KNOWLEDGE_PACK_GENERATION.txt
   - italus_saga_architecture_map.txt
   - ITALUS_HISTORICAL_EVENT_BACKBONE.txt
   - ITALUS_SCENE_GENERATOR_MATRIX.txt

2. Book pack canon
   - ITALUS_KNOWLEDGE_PACK_BOOK_XX.txt
   - single runtime artifact for the requested book

3. Accepted local continuity
   - book_state.json
   - chapter_continuity_digests.json
   - accepted scene records
   - session state

      ▼

      ▼

      ├ resolve canon context
      ├ load continuity state

      ├ coverage analysis
      ├ Prompt Builder

      │

      │
      ▼

      │
      ▼

      │
      ├ backup canon files
      ├ ensure chapter exists
      ├ create scene record
      ├ update coverage
      ├ update chapter digest
      ├ update book state
      └ update session state
      ▼

AUTHORITY ORDER FOR VALIDATION
------------------------------
Validation should resolve authority in this order:

1. accepted local continuity
2. explicit request metadata
3. book pack canon
4. global canon
5. heuristics only if a stronger layer is unavailable

DESIGN RULES
------------
1. Packet Engine validates the canon package.
2. Guardian Engine validates the requested scene.
3. post_generation_canon_validator validates the generated prose.
4. Book pack canon is one artifact, not a separate compressed canon layer.
5. Prompt text is for AI consumption; structured validation context is for validator consumption.
6. As the pipeline matures, validation responsibilities should move upstream where appropriate,
   but post-generation prose validation remains required.
